# 月詠（つくよみ）— 願いと問いのノート

強く思い、問いを立て、その問いを磨き、執着せず、小さな気づきを拾う。
それを月の満ち欠けのリズムに乗せて続けるための、個人用の道具です。

サーバーもアカウントもありません。記録はすべて自分の端末の中だけにあります。

---

## スマホで使う

### 方法1：1枚のファイルを送る（すぐできる）

```
node build.js     →  dist/tsukuyomi.html
```

CSS も JavaScript もアイコンも全部入った、**1枚だけの HTML ファイル**ができます。
これを自分あてにメールするか、AirDrop / Google ドライブでスマホに送って開けば、
それだけで動きます。サーバーもインターネットもいりません。

ただしファイルとして開く形なので、ホーム画面への追加はうまく働きません。
毎日使うなら、次の方法2をおすすめします。

### 方法2：GitHub Pages で URL にする（毎日使うなら）

ビルドの仕組みは要りません。素の HTML なので、**ブランチをそのまま配信**できます。

1. **Settings → Pages** を開く
2. **Source** を `Deploy from a branch` にする
3. **Branch** を `claude/personal-wish-fulfillment-tool-nriruw`、
   フォルダを `/ (root)` にして **Save**
4. 1〜2分待つと、同じ画面の上に URL が出ます

URL はこうなります。

```
https://west-takayama.github.io/-2026.8-17/
```

> リポジトリが**公開**である必要があります（Pages は無料プランだと公開リポジトリのみ）。
> 公開されるのは**アプリの中身（コード）だけ**です。
> 願い・問い・気づきはあなたの端末のブラウザにしか無く、
> リポジトリにも、どのサーバーにも送られません。他人には白紙のアプリが見えるだけです。
>
> GitHub Actions で自動公開する方法も試しましたが、
> Pages を有効化する API に workflow の権限が届かず
> （`Resource not accessible by integration`）、上の手動設定のほうが確実でした。
> 一度設定すれば、あとは push するたびに自動で更新されます。

置き場所は GitHub でなくても構いません。Netlify や Vercel なら、
このフォルダをそのままドラッグするだけで動きます（ビルド設定は不要です）。

## 願いの7つの原則が、どの機能になっているか

いただいた箇条書きを、そのまま機能に対応させました。

| 大切にしたいこと | かたち |
|---|---|
| 強く思うこと | 願いごとに **強さ（1〜5）** を記録。「なぜ、それを願うのか」と「叶ったときの情景」を必ず書く欄がある |
| 常に問いを立てること | 〈今日〉に **今日の問い** が毎日出る。月相ごとに32個の問いの種を用意してあるので、思いつかない日でも途切れない |
| その問いの質を高めること | 問いを消さずに **「磨く」**。前の問いを親として残し、新しい問いを子にして系譜をたどれる。3軸の自己採点と、言い回しから癖を拾うコーチ付き |
| 執着しないこと | **握り（1〜5）** を強さとは別に記録。**「次の満月まで、そっと置く」** で一覧から隠せる。**「手放す」** は失敗箱ではなく、叶ったのと並ぶひとつの完了 |
| 小さな気づきを感じること | 願いごとに **兆し** が集まる。「この願いに、7つの小さなものが届いています」という形で見える |
| 日々の気づきをメモする | 〈今日〉のトップに書き込み欄。**偶然／直感／夢／兆し／気づき／感謝** の6種類。書いた日が続くと日数が出る |
| 点と点がつながること | 〈符合〉。書いた瞬間に過去の記録と照合して「これは3週間前の◯◯と似ています」と知らせ、**星図**にパターンを描く |
| 月のリズムで区切ること | 〈儀式〉。**満月**は一巡りを振り返って感謝と手放し、**新月**は願いを言い直して種をまく。声をかけるだけでなく、その場で書ける流れになっている |
| 毎日の調子を知ること | 〈今日〉で**睡眠・調子・余白・体重**。〈調べ〉が「よく眠れた日ほど握りがゆるい」のような形にして返す |
| ためた記録から学ぶこと | 〈調べ〉。推移・つながり（相関）・曜日と月相のリズム・書いている時間・積み上がりを一枚で |
| 月の満ち欠けを意識する | すべての記録に月相が刻まれる。新月と満月の日は画面上部で呼びかける。〈月〉に周期の暦と、自分がどの月相でよく気づくかの集計 |
| 叶ったらチェック | 一覧の丸を押すと ✓。**叶った日の月の姿**が一緒に記録され、振り返りを書き残せる |

## 設計で考えたこと

### 1. 「強さ」と「握り」を、わざと別々に測る

このアプリの中心にある判断です。

ふつうの目標管理アプリは、願いに対する状態を「進捗％」ひとつに潰します。
でもそれだと、いただいた原則のうち **強く思うこと** と **執着しないこと** が
同じ軸の上で殴り合ってしまいます。強く思うほど執着していることになってしまう。

この2つは本来べつのものです。だから2本の線として記録します。

- **強さ** … 芯からそれを思っているか（高いほどよい）
- **握り** … 叶わないと困る、と感じているか（低いほどよい）

願いの画面には、この2本が折れ線で並びます。
**強さが上がりながら、握りが下がっていく** ——それがこの道具の目指す形です。
言葉でも読み取りを出します。

> 強さ5・握り1 →「いちばん良い状態です。強く思いながら、結果はゆだねられています。」
> 強さ2・握り5 →「思いは薄いのに、離せない状態です。この願いは、まだ本当に自分のものでしょうか。」

握りが2回続けて4以上になると、手放すための問いを立てるボタンが出ます。

### 2. 問いは消さない。上に重ねる

「問いの質を高める」を機能にするには、質を測るだけでは足りません。
**磨いた履歴が残ること**が本体だと考えました。

問いを書き直すのではなく「磨く」と、前の問いが親として残り、新しい問いが子になります。
あとから来歴を開くと、こう並びます。

```
1  なぜ私は書けないのか
2  どうすれば、私は毎朝10分だけ書きはじめられるだろう？
```

この2行の差が、自分が進んだ距離です。最初の問いを消してしまうと、それが見えません。

質の見立ては3軸の自己採点（各0〜3、合計9点）にしました。
自動採点にしなかったのは、**自分で見立てること自体が練習だから**です。

- 開かれているか（はい／いいえで終わらない）
- 自分に向いているか（自分で動かせる範囲にある）
- 動きにつながるか（今日の一歩が見えている）

そのうえで、書いている最中に言い回しの癖を拾って声をかけます（通信もAIも使わない、日本語の規則だけの仕組みです）。

- 「なぜ〜ないのか」→ 犯人さがしになりかけているかも。「どうすれば〜できるだろう？」へ
- 「〜べき」→ 誰かの声が混ざっているかも。「本当は、私はどうしたい？」へ
- 「あの人が」「会社が」→ 矢印が外を向いています
- 「いつか」→ 時期がぼやけています

### 3. 執着しないことを、押せるボタンにする

「執着しない」は心がけでは続きません。動作にする必要があります。
そこで2つ用意しました。

- **そっと置く** … 次の満月まで、その願いを〈今日〉から隠します。思い出さないでいられる日々が、いちばんよく効きます
- **手放す** … 願いを終わらせます。ただし失敗箱には入れません。〈叶った〉と並んで「手放した」として残ります

「叶わなくても、私が本当に欲しかったものは何だろう？」——この問いをワンタップで立てられるようにしてあるのも、同じ考えからです。

### 4. 月を、飾りではなく時計として使う

月相はただの表示ではなく、アプリのリズムそのものにしました。

| 相 | テーマ | すること |
|---|---|---|
| 新月 | 種をまく | 願いを書く／言葉にし直す |
| 三日月 | 小さく動く | 5分でできる一歩 |
| 上弦の月 | 壁と向き合う | ひとつ決める |
| 十三夜月 | 問いを研ぐ | 問いを磨く |
| 満月 | 感謝と手放し | 感謝を書く／握りしめを確かめる |
| 十六夜月 | 分かち合う | 気づきを言葉にする |
| 下弦の月 | 手放す | ひとつ手放す |
| 有明月 | ゆだねる | 休む |

- **今日の問い** は、今日の月相に合った種から日替わりで出ます
- 新月と満月の日は、開いた瞬間に呼びかけが出ます
- すべての記録に月相が刻まれるので、あとから「あの満月の頃に書いたな」とたどれます
- 〈月〉に、自分がどの月相でよく気づきを書いているかの集計が出ます。これも一種の問いです

月齢は Meeus の位相角の式（主要項）で計算しています。
「基準の新月からの日数を29.53で割る」簡易法だと最大半日ずれ、
「次の満月」の日付が一日まちがうことがあるためです。現在の誤差はおおむね一時間以内です。

### 5. 符合：点が線になるところを、図にする

偶然・直感・夢を書きとめると、**保存した瞬間に**過去の記録と照らし合わせて、
似ているものをその場に出します。

> **いま書いたことは**　夢／青い鳥が窓の外にとまっている夢を見た
> **2日前の記録と** … 夢のなかで、青い鳥を追いかけて山をのぼっていた
> 　・「青」「鳥」「夢」が重なっています
> 　・どちらも三日月の日です
> **3週間前の記録と** … 古本屋でたまたま開いた本に、青い鳥の話が載っていた
> 　・「青」「鳥」が重なっています

**照合のしくみ**（通信もAIも使いません）

形態素解析器も積んでいません。10年後も動くことを優先したので、
かわりに2つの見方を組み合わせています。

- **語** … 漢字・カタカナ・英数字のかたまりを語として拾う。意味の芯を取る
- **2文字の連なり** … ひらがなを含む言い回しの近さを拾う

どちらも IDF（めずらしさ）で重みづけします。「今日」「思う」のようにどの記録にも出る語は
自動的に軽くなり、「鳥」「青」のように滅多に出ない語が強く効く。
**シンクロを感じるのは、まさに滅多に出ないものが重なったときだから**です。

ここで一番苦労したのは、日本語では「知らない人」から `知` `人` という語幹が取れてしまい、
それだけで「重なっている」と判定されてしまう点でした。
そのままだと `知`+`人` の組が `青`+`鳥` の組を追い越します。
動詞・形容詞の語幹と汎用名詞だけを落とすことで、この誤検出を消しています。

言葉以外の符合も見ます。

- 同じ月相の日に起きている
- ちょうど月ひと巡りぶんの間隔が空いている
- 同じ願いに紐づいている

しきい値は**厳しめ**にしました。何でも「符合」になってしまうと、体験そのものが安っぽくなるからです。
取りこぼすほうがまだいい。

**星図**

記録は月の周期の上に星として置かれます。

- **角度** … その日の月相（真上が新月、右へ満ちて、真下が満月）
- **半径** … 何巡り前か（古いものが内側、新しいものが外側）

こうすると**同じ月相のときに起きたことが、同じ方角にそろいます**。
響き合ったものどうしは線でつながります。星をつつくと、その記録と響きが読めます。

何ヶ月か続けたあとで「自分は毎回この頃に同じことを書いている」と気づく——
それがこの画面のいちばん見せたいものです。

そのほか、**くり返し現れている言葉**（「夢×4／45日にわたって」）も一覧にしています。
つついた言葉で記録を検索できます。

### 6. 満月と新月の儀式：約束したリズムを、実際に回す

このアプリは長いあいだ「満月は感謝と手放しの日です」と**声をかけるだけで、何もしませんでした**。
月をリズムの中心に据えると設計しておきながら、実際に何をするかは本人の意志任せだった。
そこが一番の穴だったので、ここを埋めました。

**満月の儀式 — 感謝して、手をひらく**

1. **この一巡りにあったこと**（自動でまとまります）
   書きとめた数、立てた問い、叶った願い、しるしをつけたもの、
   そして育てている願いごとに「握り 4 → 2　ずいぶん手がひらきました」
2. **すでに叶っている部分を、三つ** — 書いたものは〈感謝〉として記録にも残ります
3. **握りしめを、確かめる** — 願いごとに、いま握っている強さを選び直す
4. **ひとつ、手放す** — 願いそのものでなくてよい。「こうでなければ」を一つ外す

**新月の儀式 — 種をまく**

1. **前の一巡りにあったこと** ＋ **前の満月に自分が書いたこと**（感謝と、手放したもの）
2. **願いを、言い直す** — 一巡りで輪郭が変わっていれば、いまの言葉に
3. **この一巡りの、意図** — 願いとは別に、次の29日をどんな時間にしたいか
4. **持ち歩く問いを、ひとつ**

満月に書いたものが次の新月に戻ってくるので、**一巡りが閉じて、次が始まります**。
過去の儀式は〈月〉から読み返せます。

段階を分けたウィザードにはしていません。スマホで「次へ」を押させると、
途中でやめたときに何も残らないからです。1枚の紙のように上から下へ並べ、
書けたところだけが残ります。その日でなくても開けます。

> 握りの目盛りは、前回の値をあらかじめ選んだ状態にはしていません。
> 前回の値が入っていると、それを追認するだけになりやすいためです。
> 前回の数字は横に小さく出すだけにして、毎回選び直してもらいます。

この作業中に、月の計算のほうにも不具合が見つかりました。
「直近の新月」を求める関数が、朔望月ぶん戻ってから次の新月を探す作りだったため、
戻し幅が 29.53 日をわずかに超え、**新月を過ぎた直後の十数時間だけ、
ひとつ前の新月を返して**いました。よりによって新月の儀式を開く時間帯です。
いま周期のどこにいるかから戻す量を決めるように直し、12周期ぶんを検査して確認しました。

### 7. コンディションと〈調べ〉：記録を、自分についての知識に変える

〈今日〉で毎日記録します。**昨夜の睡眠**（時間）、**調子**（1〜5）、**余白**（1〜5）、**体重**（kg）。

体重だけは入力の性質が違います。範囲が広くて刻みが細かいので、
毎朝キーボードを出させると続きません。**前回の値を入れておいて、± 0.1 のボタンで動かすだけ**にしました。
ふつうは1〜3タップで終わります。

目標体重も、増減の色分けも置いていません。数字に良し悪しを付けはじめると、
このアプリがいちばん避けたい「握りしめ」を、こちらから作ってしまうからです。
出すのは数字と、その動きだけです。

大事なのは、これを**単体の記録として置かない**ことです。
このアプリには「なぜ今日は気づけたのか、なぜ握りしめてしまうのか」を説明する変数が
ありませんでした。睡眠と余白は、その空白を埋めるために入れています。

〈調べ〉が返してくるのは、たとえばこういう文です。

> **よく眠れた日ほど、握りしめがゆるい**　　睡眠 × 握り
> 　眠れていないだけなのに「この願いは無理かも」と思えてくることがあります。
> 　45日ぶんの記録から　強さ はっきり（r = −0.76）

〈調べ〉には、ほかに以下が並びます。

- **見わたす** … 7日／28日／90日／すべてで、平均と推移の折れ線
- **つながり** … 上のような相関（あとで詳しく）
- **くり返しているリズム** … 曜日ごと・月相ごとの平均（調子／睡眠／余白／握り／書いた数で切り替え）
- **書いている時間** … 何時台に書いているか
- **積み上がったもの** … 記録した日数、連続、最長連続、月ごとの本数

満月の儀式にも「**この一巡りの、からだ**」が加わり、
平均睡眠と、その周期のなかで睡眠と握りが連動していたかが出ます。

#### 体重だけは、生の数字を相関にかけない

体重は他の項目と性質が違います。**ゆっくり一方向に動く**のです。

45日かけて体重が下がり、そのあいだにたまたま調子が上向いていたとします。
相関を取ると強い数字が出ます。でもそれは**2本の傾きが並んでいるだけ**で、関係ではありません。
そして、この手の見せかけの相関は、いちばん信じ込みやすい。

そこで、前後3日の移動平均からのずれ（＝その日が「ふだんより重いか、軽いか」）を作り、
**相関にはこちらだけを使っています**。ゆっくりした増減を取り除いて、日々の揺れだけを残す。
生の体重は、推移の折れ線と平均の表示にしか使いません。

効き目は実際に確かめました。体重と調子が無関係に、ただ別々に傾いているだけのデータで、

```
生の体重 × 調子   r = −0.73   ← 強い関係に見える（でも見せかけ）
ずれ    × 調子   r = −0.03   ← 正しく「関係なし」
```

画面には何も出ません。一方、日々の揺れが本当に調子と連動している場合は
r = −0.83 として拾えることも確かめています。

#### ここでいちばん気をつけたこと：言いすぎないこと

記録が10日ぶんもあれば、相関はいくらでも出ます。でもそのほとんどは偶然です。
それを「あなたはこうです」と言い切ると、**当たっていないことを信じ込ませてしまう**。
願いと執着を扱う道具でそれをやるのは、いちばんやってはいけないことだと思っています。

だから4つの制約を置きました。

1. **14日ぶんたまるまで、何も言わない。** それまでは「あと何日で読みはじめます」だけを出します
2. **必要な相関の強さを、日数で変える。** これが一番大事なところです。
   14日ぶんしかないときの r = 0.4 は偶然でふつうに出る値で、40日ぶんの r = 0.4 とは重みが違う。
   固定のしきい値だと、記録が少ない時期にいい加減なことを言ってしまいます。
   そこで `max(0.35, 2.2/√n)` を下限にしました（14日なら 0.59、40日なら 0.35）。
   係数を 1.96 より大きく取っているのは、9通りの組を一度に調べているぶん、
   偶然の当たりが増えるのを見込んでいるためです
3. **調べる組み合わせを、あらかじめ決めておく。** 総当たりにすると、
   数が多いだけ偶然の当たりが増えます。意味を説明できる12組だけを見ています
   （組を増やしたら、係数もそのぶん上げます）
4. **「〜だから〜になる」とは言わない。** どちらが原因かは分からないので、
   必ず根拠の日数と r を添えて、判断は本人に返します

でたらめな記録を12回ぶん（144通りの検定）流して、誤って「つながり」と言ってしまうものが
0件であることを確認しています。

### 8. 技術：何も使わないという選択

```
index.html            画面の骨格
assets/style.css      見た目（夜の色に固定）
src/moon.js           月齢・朔望・月の描画
src/store.js          保存と読み出し（localStorage）
src/ui.js             描画の小道具
src/coach.js          問いの癖を拾う規則
src/seeds.js          月相ごとの問いの種
src/resonance.js      記録どうしの照合（符合の心臓部）
src/analysis.js       相関と集計（調べの心臓部）
src/echo-view.js      「前の記録と響いています」の表示
src/views/*.js        画面ごとの描画（today / wishes / questions / notices / sync / ritual / moon / settings）
src/app.js            画面の切り替え
sw.js                 圏外でも開けるようにするだけのもの
```

フレームワークもビルドもパッケージも使っていません。理由は3つです。

1. **10年後も動くように。** 願いは数年単位のものです。数年でビルドが壊れる道具に預けたくありません
2. **どこにも送らないように。** 願いは、いちばん私的なものです。localStorage だけに置き、通信は一切しません
3. **すぐ直せるように。** 素のHTML・CSS・JavaScriptなので、思いついた機能をその場で足せます

## 記録を守る

記録は **いま使っているブラウザの中だけ** にあります。
サーバーには何も送られませんが、裏を返せば、ブラウザの履歴を消したり端末を替えたりすると失われます。

〈設定〉から2種類の書き出しができます。

- **JSON** … 復元用。読み込めば元どおりになります
- **テキスト** … 読み返す用。願い・問い・気づきが月相つきの読み物になります

**満月の日に書き出す**——それくらいの習慣をおすすめします。

## これから足せそうなこと

いま作らなかったけれど、使ってみて欲しくなりそうなものを挙げておきます。

- **問いの再会** … 昔立てた問いを、忘れた頃にもう一度出す。「この問いから89日経ちました」
- **年に一度の振り返り** … 一年ぶんの願いと問いを一枚にまとめて読む画面
- **写真を添える** … 兆しは、言葉より写真のほうが残ることがあります
- **符合の予告** … 「そろそろ、去年の同じ月相であれを書いた頃です」と先に知らせる
- **端末間の同期** … ただしこれは、記録を外に出すということでもあります。慎重に
